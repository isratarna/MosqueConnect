# Internationalisation (English / বাংলা)

The interface is available in English and Bangla. Switch with the **EN | বাং** control in the navbar. The choice is saved in `localStorage` (`i18nextLng`) and survives a reload; with nothing saved, the browser language decides (`bn-BD` → Bangla, anything else → English).

Only the **interface** is translated. Text that people type in (mosque names, announcements, events, campaign copy, notes) is shown exactly as written, and so are the messages the API returns. See [Known limits](#known-limits).

## Where things live

| Path | What it holds |
| --- | --- |
| `apps/web/src/i18n/index.js` | i18next setup, language detection, persistence, `<html lang>` and tab title |
| `apps/web/src/i18n/locales/en.json`, `bn.json` | All strings, grouped by area (`nav`, `home`, `browse`, `mosque`, `prayer`, `admin`, `common`, …) |
| `apps/web/src/i18n/translate.js` | `translate(key, options)` for code that runs outside a component |
| `apps/web/src/hooks/useLocale.js` | `{ t, language, locale }` for components that format values |
| `apps/web/src/utils/intl.js` | Locale-aware numbers, dates, times (`formatNumber`, `formatTimeOfDay`, `formatDateTime`, …) |
| `apps/web/src/utils/labels.js` | Labels for statuses and categories the API sends as codes |
| `apps/web/src/utils/network.js` | `networkFetch`, which words a failed connection in the active language |
| `apps/web/src/components/LanguageSwitcher.jsx` | The EN \| বাং control |

## Adding or changing text

1. Add the key to **both** `en.json` and `bn.json`, under the area it belongs to.
2. Use it: `const { t } = useTranslation();` then `t("area.key")`.
3. Run `npm run test --workspace=apps/web`. The test in `src/i18n/locales.test.js` fails if a key is missing from either file, if `{{placeholders}}` or `<tags>` differ between them, if the source uses a key that does not exist, or if a key is no longer used.

Conventions:

- **Interpolation**: `t("browse.showing", { start, end, total })` with `{{start, number}}` in the string. The `number` format renders Bangla digits automatically.
- **Plurals**: define `key_one` and `key_other` and pass `count`.
- **Links inside a sentence**: `<Trans i18nKey="…" components={{ browse: <Link to="/browse" /> }} />` with `<browse>…</browse>` in the string.
- **Data files** hold translation keys (`labelKey: "facility.wudu"`), not text. The component calls `t(labelKey)`.
- **Values that go to the API stay as they are.** Option `value`s (for example campaign and event categories) remain English; only the label shown to the user is translated.
- **Keys built at run time** (`t(\`status.${value}\`)`) must be listed in `DYNAMIC_FAMILIES` in `locales.test.js` so the test can check them. Prefer the helpers in `utils/labels.js`, which fall back to the raw value for anything unexpected.

## Numbers, dates and times

Never call `toLocaleString`, `toLocaleTimeString` or `new Intl…(undefined, …)` directly. Use `utils/intl.js` with the locale from `useLocale()`:

```jsx
const { t, locale } = useLocale();
formatClockTime("13:30", locale); // en: "1:30 PM"   bn: "১:৩০ দুপুর"
formatCampaignMoney(12500, "BDT", locale); // bn: "১২,৫০০৳"
```

`en` formats as `en-BD` and `bn` as `bn-BD`. In Bangla the part of the day is written out (ভোর, সকাল, দুপুর, বিকাল, সন্ধ্যা, রাত্রি) instead of AM/PM.

Internally everything stays in the API's form: 24-hour ASCII times such as `"13:30"`. Formatting only happens at the point of display.

## Fonts

`index.html` loads **Hind Siliguri** from Google Fonts. `:lang(bn)` in `index.css` applies it, and each explicit `Manrope` / `Playfair Display` stack lists it as a fallback so Bangla glyphs never fall back to a random system font. Bangla also gets a taller line height and no letter-spacing.

## Known limits

- **Server messages** (validation errors, "Already registered…") come from the API in English and are shown as returned. The messages the app words itself are translated. Translating the rest means adding locales to the Laravel API.
- **Google Maps** draws its own controls and labels in the language it was loaded with. The language is fixed when the app first loads, so after switching it the map updates on the next page load.
- **Native pickers** (`<input type="date">`, `type="time"`) follow the browser's language, not the app's.
- **Backend-supplied labels** that are not in `utils/labels.js` (a new status or category) are shown untranslated rather than failing.
